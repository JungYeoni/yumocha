# [Methodology] 구조환경지표 결측 처리 모듈 사전 구현 — 2026-08-04

## 1. 목적

이번 문서는 #70 구조환경지표 결측 처리 모듈의 사전 구현 범위를 정리하고, #80에서 구축된 기준 패널과 실제 연동하기 전에 아직 수행하지 않은 항목을 명확히 구분한다.

## 2. 대상 데이터와 검증 방식

- 대상 버전·기간: #80에서 2026-08-04 기준으로 확정한 2016–2024년, 28개 지표 × 전국 및 17개 시도의 보간 전 long 패널 스키마를 연동 대상으로 삼는다. 이번 사전 구현에서는 실제 패널 파일을 입력하지 않는다.
- 데이터 분할: 해당 없음. 이 모듈은 모델 학습이나 성능 추정이 아닌 결정론적 전처리이므로 날짜·비율 기반 train/validation/test 분할과 stratify를 수행하지 않는다.
- 평가 지표·CV fold: 해당 없음. 예측 평가나 교차검증 대신 결측 유형별 처리값과 상태 열의 일관성을 단위 테스트로 검증한다.

## 3. 핵심 가정과 방법론적 제약

- 입력은 지역·지표·연도·측정값을 한 행으로 갖는 long 패널이며, 연도는 숫자형 정수로 정규화할 수 있어야 한다.
- 누락된 연도 행은 자동 생성하지 않는다. `expected_years`가 주어지면 완전성을 검증하고, 불연속 연도 입력의 보간은 실제 연도 간격을 사용한다.
- 구조적 결측은 명시적인 플래그 열에 의존하며, 해당 결측을 가로질러 보간하지 않는다.
- 기존 `fillna()` 사용처와 지표별 노트북은 텍스트·QA 보조 처리 또는 개별 원자료 규칙에 한정되어, 결측 유형·처리 방법·대체 여부·분석 포함 여부를 함께 반환하는 공통 long 패널 계약을 제공하지 않는다. 이 차이 때문에 별도 모듈로 구현한다.

## 4. 한계와 잠재 편향

- 구조적 결측 플래그가 없으면 일반 결측과 원자료 자체 결측을 구분할 수 없다.
- 선행·후행 결측의 기본 hold 전략은 실제 추세를 평탄화할 수 있다.
- 구조적 결측 경계 때문에 보간할 수 없는 일반 결측은 원래 NA를 유지하고 분석에서 제외하므로, 사용 가능한 분석 기간이 줄어들 수 있다.
- 실제 패널 적용 전 단계이므로 지표별 결측 원인과 대체금지 여부에 대한 도메인 검토는 아직 반영되지 않았다.

## 5. 이번 사전 구현 범위에서 수행하지 않은 항목

- #80 기준 패널에 결측 처리 모듈을 실제 적용하지 않음
- 지표·지역·연도별 결측 원인 및 대체금지여부 매핑을 수행하지 않음
- 결측 처리 전후 패널 생성 및 민감도 비교를 수행하지 않음

따라서 현재 산출물은 #70 완료본이 아니라, #80 기준 패널의 실제 결측 원인 매핑 및 처리 패널 생성 전 단계인 전처리 모듈·테스트 준비본이다.
