# 2016년 LLM 체크포인트 오연결 복구 결과

## 1. 문제

2016년 세부사업 정제본에서 일부 `주요내용_정제`가 같은 행의
`주요내용`을 정제한 결과가 아니라 다른 세부사업의 주요내용으로 저장된
사례를 확인했다. TF-IDF 최종 모델은 `세부사업명+주요내용_정제`를
사용하므로 2016년 분류 입력과 예측 결과도 영향을 받는다.

대표적으로 울산 원본행 2795의 `직장보육시설의 운영`에는 원래
`시청어린이집 위탁 운영`이 들어가야 하지만, 기존 정제본에는 원본행
2800의 `임신교직원 편의용품 구입비 지원`이 연결돼 있었다.

## 2. 원인

기존 2016 노트북은 LLM 체크포인트에 DataFrame 인덱스와
`주요내용_정제`만 저장했다. 이후 필터링이나 행 구성이 달라져도 같은
인덱스의 과거 결과를 현재 행에 그대로 재사용했기 때문에 사업과 정제
내용의 신원이 어긋났다.

기존 체크포인트:

- 파일: `data/interim/2016_llm_정제_체크포인트.csv`
- 신원 컬럼: 없음
- 원문 해시: 없음
- 재사용 기준: DataFrame 인덱스

## 3. 수정

2016 노트북의 수동 체크포인트 코드를 공통
`run_checkpointed_refinement()` 호출로 교체했다.

- 신원: `지역+원본행+세부사업명`
- 원문 검증: `주요내용_원문_SHA256`
- 신규 체크포인트:
  `data/interim/2016_llm_정제_체크포인트_v2.csv`
- 구형 체크포인트는 재사용하지 않는다.
- LLM 실행 기본값은 `false`이며 명시적으로 `RUN_LLM=true`를 설정한
  경우에만 호출한다.
- 체크포인트의 신원 또는 원문 해시가 현재 입력과 다르면 해당 행을
  재실행한다.

## 4. LLM 재정제 결과

구형 체크포인트를 폐기하고 v2 체크포인트로 2016년 전체 4,494행을
재처리했다. 결측 행은 호출하지 않았고, 숫자·금액·비율·범위 보존
검사를 통과하지 못한 결과는 원문을 유지했다.

| 검증 항목 | 결과 |
|---|---:|
| 전체 행 | 4,494 |
| LLM 정제 성공 | 4,354 |
| 원문 결측 | 136 |
| 보존 위반으로 원문 유지 | 4 |
| 호출 실패 | 0 |
| 신원 불일치 | 0 |
| 원문 해시 불일치 | 0 |
| 체크포인트와 wide 결과 불일치 | 0 |
| 지역 | 17개 |
| wide 행 | 4,494 |
| long 행 | 8,988 |
| `연도+지역+원본행` 중복 | 0건 |
| long 행 수가 wide의 2배가 아닌 지역 | 0개 |

보존 위반 4건은 경남 2건, 대전 1건, 경북 1건이다. LLM 출력에서
원문의 숫자 또는 금액·비율·범위가 달라져 자동 채택하지 않고 원문을
보존했다.

- 경남 원본행 7171: `자살예방 및 지역 정신보건사업`
- 대전 원본행 2605: `시 노인복지관 운영 지원`
- 경북 원본행 6784:
  `다문화가족의 안정적 정착을 위한 맞춤형 서비스 확대`
- 경남 원본행 7428: `도민 무료창업강좌 개최`

기존에 확인한 울산 원본행 2795, 2833, 2839의 오연결도 해소됐다.

재정제 후 8개년 TF-IDF 분류 대상을 다시 취합한 결과는 다음과 같다.

| 검증 항목 | 결과 |
|---|---:|
| 대상 연도 | 8개 |
| 지역 | 17개 |
| 연도×지역 조합 | 136개 |
| 통합 행 | 50,678 |
| `주요내용_정제` 결측 | 369건 |

기존 결측 363건보다 6건 늘어난 것은 구형 체크포인트가 원래 주요내용이
비어 있던 행에도 다른 행의 내용을 잘못 붙였던 결과를 제거했기 때문이다.

## 5. 재현성 및 방법론적 제약

- 데이터셋 버전: 2016년 시행계획 원자료를 2026-07-29에 v2
  체크포인트로 재정제한 wide/long 정제본과, 이 정제본을 반영해 같은
  날 재생성한 2016~2020·2022~2024년 TF-IDF 통합 입력을 기준으로 한다.
- 대상 기간: LLM 재정제는 2016년 17개 시도, 통합 입력 QA는 8개년
  136개 연도×지역 조합을 대상으로 한다.
- 분할 전략·CV fold: 해당 없음. 이번 작업은 예측모형의 성능 평가가
  아니라 전체 대상 행의 체크포인트 신원 복구와 정제본 재생성이다.
- 평가 지표: 체크포인트 신원·원문 해시 일치 건수, wide 결과 일치
  건수, 키 중복, wide/long 행 수, LLM 실패 및 보존 위반 건수를
  사용했다.
- 핵심 가정: `지역+원본행+세부사업명`과 원문 SHA-256이 같을 때만
  동일한 정제 입력으로 본다. 숫자·금액·비율·범위 보존 위반은 원문을
  유지하는 것이 임의 수정값을 채택하는 것보다 안전하다고 가정한다.
- 방법론적 제약: 보존 검사는 숫자와 특정 표기 손상을 탐지하지만 문장의
  의미가 미세하게 변한 경우를 모두 검출하지는 못한다.
- 한계 및 잠재 편향: 원자료 자체의 오타·누락은 이번 복구 범위 밖이며,
  주요내용이 결측인 136건은 텍스트 분류에서 사업명 정보에 더 크게
  의존한다. 보존 위반 4건에 원문을 유지한 조치는 해당 행의 정규화
  정도를 다른 행보다 낮게 만들 수 있다.

## 6. 후속 처리

1. #65 모델링 브랜치에서 최신 TF-IDF 통합 입력을 반영해 예측
   CSV·QA·검토 Excel을 재생성한다.
2. 검토 Excel은 `연도→지역→원본행` 순으로 저장하고 저신뢰 여부는
   필터와 색상으로 제공한다.

PR #66의 기존 2016년 예측 결과는 본 복구 이전 입력으로 생성됐으므로
재생성 전까지 사용하지 않는다.
