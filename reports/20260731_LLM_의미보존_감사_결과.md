# LLM 정제 의미보존 감사 1~3단계 결과

## 1. 범위와 판정 기준

- 대상: 2016~2024년 17개 시도 wide 정제본
- 입력 스냅샷: 2026-07-31 기준 저장소의 연도별 최종 wide CSV와 LLM
  체크포인트. 원자료는 Git 비추적 파일이므로 저장소 커밋 해시만으로 완전한
  원자료 버전을 식별할 수 없다.
- 분석 기간: 2016~2024년
- 데이터 분할: 해당 없음(모델 학습·평가가 아닌 전수 규칙 감사)
- 평가 지표·CV fold: 해당 없음. 자동 후보 건수·후보율과 사람 전수검토 결과를
  기록했다.
- 분석 단위: `연도·지역·원본행`
- 대상 행: 총 57,979행
- 이번 단계에서는 원본·체크포인트·wide·long을 수정하지 않고 감사 후보만
  생성했다.
- 결정적 보존 위반:
  - 원문 결측·빈 문자열인데 정제문이 생성됨
  - 정제문 결측
  - 숫자 시퀀스 불일치
  - 금액·퍼센트·범위 불일치
  - 추출 가능한 고유명사 불일치
- 사람 검토 후보:
  - 정제문에만 `원문:` 라벨 추가
  - 공백 제거 문자 수 기준 길이비가 0.5 미만 또는 1.5 초과

공통 검증 함수는 `src/features/llm_refine.py`의
`semantic_preservation_flags()`에 구현했다. 감사 재현 코드는
`scripts/audit_llm_semantic_preservation.py`, 2023년 환각 복구 재검증은
`scripts/verify_2023_hallucination_recovery.py`에 분리했다.

탐지 규칙은 표면 문자열·수량·고유명사 차이를 이용하므로 의미가 유지된
표기 정리를 거짓 양성으로 잡거나, 숫자와 길이가 비슷한 의미변경을 거짓
음성으로 놓칠 수 있다. 따라서 자동 후보를 오류로 확정하지 않고 사람이
전수 확인했다. 과거 체크포인트 일부에는 안정적인 행 키와 원문 해시가 없어
checkpoint·wide 사이의 개별 행 추적에 제한이 있다는 점도 잠재 편향으로
남는다.

## 3. 2023년 환각 9건 복구 재검증

### 3.1 확인된 복구

- 체크포인트 7,543행, wide 7,543행, long 15,086행을 검사했다.
- wide의 `지역·원본행` 중복은 0건이다.
- 모든 wide 행에 대응하는 long 행은 정확히 2행이며, wide와 long 사이
  `주요내용_정제` 불일치는 0건이다.
- 기존 사고의 대표 가짜 값인 `1,200,000,000원`, `043-123-4567`,
  `youth@boeun.go.kr`은 체크포인트·wide·long 모두 0건이다.
- 보고서에 언급된 충북 대표 3개 사업은 원문과 정제문이 모두 빈 값이다.
  - 원본행 5030 `아동급식 확대 지원`
  - 원본행 5033 `지역아동센터 냉난방비 지원`
  - 원본행 5339 `보은군 청년 활성화 공모사업`

따라서 기존 보고서가 설명한 **가짜 숫자·행정문서 환각 사고의 복구는 현재
산출물에서도 확인된다.**

### 3.2 추가로 발견된 고위험 문제와 복구

2023년 원문 `주요내용`이 빈 행은 실제로 67건이다.

- 최초 감사 시 정제문도 빈 값: 10건
- 최초 감사 시 정제문에 값이 생성됨: **57건**

57건은 충북 44건, 전남 11건, 충남 1건, 제주 1건이다. 다수는 빈 원문에
`세부사업명`과 같거나 유사한 문장이 들어가 있다. 기존 숫자보존 검사는
숫자가 없는 사업명을 복사한 경우를 잡지 못했으므로, 숫자 환각 9건의 복구와
별개인 **빈 입력 의미보존 위반**으로 판정했다.

후속 복구에서 57건의 wide·long 값을 모두 빈 값으로 수정했고, 체크포인트는
값·순서 기반으로 동기화했다. 체크포인트에는 안정 키가 없어 57건 각각의 직접
대조는 불가능하며, 이 한계는 3.3절에 별도로 기록했다. 재검증 결과는 다음과 같다.

- 빈 원문 67건 중 정제문도 빈 값: 67건
- 빈 원문인데 정제문이 생성된 잔존: **0건**
- wide·long 정제문 불일치: 0건
- TF-IDF 예측 입력 통합본 재생성 완료

복구 전에는 `세부사업명 + 생성된 사업명`처럼 같은 정보가 중복된 분류텍스트가
만들어졌으나, 복구 후에는 세부사업명만 입력으로 사용된다. 이 57건은 후속
모델 재예측 및 예측 변경 여부 검토 대상이다.

### 3.3 체크포인트 동기화 상태

체크포인트와 wide의 `주요내용_정제` 값 다중집합을 비교하면 양쪽에 각각
15건의 차이가 있다. 표본상 PUA 불릿 제거, 줄바꿈 제거, 라벨 공백 정규화
등 후처리 차이다. wide와 long은 일치하지만 체크포인트까지 완전히 같은
상태는 아니다.

기존 체크포인트는 `주요내용_정제`와 내부 인덱스만 저장해 지역·원본행을
직접 추적할 수 없다. 따라서 후속 수정 시에는 57건을 wide에서만 고치지
말고, 신원 컬럼과 원문 해시를 포함하는 현행 공통 체크포인트 형식으로
재생성하거나 안전하게 마이그레이션해야 한다.

## 6. 2023년 빈 원문 환각 57건 복구

`scripts/apply_2023_blank_input_recovery.py`로 57건을 복구했다. 정제문 값이
전체 데이터에서 중복된 3건은 같은 문자열을 일괄 치환하지 않고, 해당 지역의
전후 고유 체크포인트 값을 앵커로 사용해 정확한 내부 인덱스를 선택했다.

- 충북: 44건
- 전남: 11건
- 충남: 1건
- 제주: 1건

복구 산출물은
`reports/yearly/2023/2023_LLM_빈원문_환각_복구검토.csv`에 기록했다. 각 행에
기존·복구 후 분류텍스트와 `예측 입력 변경·후속 재예측 필요` 판정을 포함했다.

복구 후 공통 감사를 다시 실행한 결과 2023년 후보는 71건에서 14건으로
감소했다. 이 14건은 이후 §8에서 전수 검토했다.

체크포인트와 wide 사이의 기존 후처리 차이 15건은 여전히 남아 있다. 이는
이번 57건 복구 대상과 별개이며 PUA·줄바꿈·라벨 공백 정규화 차이로 확인된
항목이다.

## 7. 2024년 의미보존 후보 36건 전수검토

2024년 자동검출 후보 36건을 원문·정제문·세부사업명 맥락으로 전수 검토했다.

- 의미보존 확인 및 정제값 유지: 28건
- 의미보존 오류 확정 및 수정: 8건

확정 오류는 다음 유형이다.

| 유형 | 건수 | 대상 |
|---|---:|---|
| 사업명·`원문:` 등 메타 라벨 추가 | 3 | 서울 194, 인천 1455, 경북 6945 |
| 내용 삭제·과도한 요약 | 3 | 세종 2654, 전남 6102, 경북 6884 |

체크포인트 앵커로 내부 인덱스를 확정했다.

수정된 정제본으로 TF-IDF 예측 입력 통합본도 재생성했다. 8건은 예측 입력이
달라졌으므로 후속 재예측 대상이며, 나머지 28건은 기존 입력을 유지한다.

상세 검토 결과:

- `reports/yearly/2024/2024_LLM_의미보존_전수검토.csv`

재감사 결과 2024년 자동후보는 36건에서 28건으로 감소했다. 남은 28건은
사람 검토에서 의미보존으로 확인된 띄어쓰기·OCR 문자·구두점 정리 사례다.

## 14. 정제값 변경 79건의 라벨·예산 연결 영향

의미보존 오류 수정으로 실제 `주요내용_정제`가 달라진 행을 연도별 검토
산출물에서 통합하고, 최신 지역별 wide와 `연도·지역·원본행` 키로 일대일

| **합계** | **79** | |

- 최신 wide와 `연도·지역·원본행` 키 일대일 연결

재정팀 검토 중인 라벨을 통합 시트의 행 순서나 텍스트로 연결하지 않고

예측과 달라진 경우에만 사람 검토한다.
