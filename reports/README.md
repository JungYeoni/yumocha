# reports/ 디렉터리 안내

보고서 성격과 연도를 기준으로 아래와 같이 구성한다 (이슈 #33).

```
reports/
├── yearly/{연도}/     # 연도별 EDA 보고서 + QA·LLM 검토 CSV (2016~2024)
├── methodology/        # 연도에 매이지 않는 공통 방법론·유틸·QA 기준 문서
├── planning/            # 작업 계획 문서
└── archive/             # 최신 문서로 대체되어 보존만 하는 과거 자료
```

## 폴더별 기준

- **`yearly/{연도}/`**: 특정 연도의 시도별 분리·정제 파이프라인 EDA 보고서와 그 연도의 QA/LLM 검토 CSV. 노트북의 `REPORTS_DIR`이 이 경로를 가리킨다.
- **`methodology/`**: 특정 연도에 종속되지 않는 공통 함수·유틸 모듈화, QA 오차율 허용기준, 멘토링 피드백 등 여러 연도에 걸쳐 재사용되는 방법론 문서.
- **`planning/`**: 시도별 예산현황 분리·정제, 세부사업 영역분류 등 작업 착수 전 계획 문서.
- **`archive/`**: 이후 문서로 대체되어 더는 최신 상태가 아니지만 최초 검증 기록으로 보존하는 자료.

## 루트에 남아 있는 문서

다음 문서들은 특정 연도 하나에 속하지 않고 2016~2025년 자료 전체 또는 여러 이슈에 걸친 작업을 다루므로, 폴더 하나를 새로 만들기보다 `reports/` 루트에 그대로 둔다:

이슈 #33 제안 구조의 `cross_year/` 폴더는 위 문서들을 억지로 묶어 넣기보다 이렇게 루트에 두는 쪽이 탐색성이 낫다고 판단해 만들지 않았다. 위 성격의 문서가 더 늘어나 하나의 폴더로 묶을 실익이 생기면 그때 `cross_year/`를 만든다.
